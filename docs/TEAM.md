# Team setup and roles

Три человека, у каждого своя зона и своя ветка. Файлы из чужой зоны не трогаем.

| Роль | Зона (файлы) | Задачи |
|---|---|---|
| **A: Дамир, ядро** | `backend/app/` | эмбеддинги, двусторонний скор в `matching.py`, чтение готовых объяснений, пересчёт после обратной связи, `/api/graph` с реальными координатами |
| **B: Шахруз, фронт и дизайн** | `frontend/` | дизайн-система, анкета, выдача топ-5, карта зала, kk/ru/en, адаптив, QR-страница |
| **C: Дулат, данные, бэкенд-скрипты и питч** | `data/`, `backend/scripts/`, `backend/tests/`, `docs/`, `README.md`, `docker-compose.yml`, презентация | генератор 100+ анкет, скрипт предрасчёта объяснений и первых фраз (LLM), тесты взаимности целей, docker compose, README, видео 3 минуты, презентация 10 слайдов, прогон жюри-сценария |

Дулат делает бэкенд-часть вне `backend/app/`, поэтому с Дамиром они не правят одни и те же файлы. Контракт между ними: Дулат кладёт `data/profiles.json` и `data/explanations.json`, Дамир их читает.

`docs/CONTRACT.md` общий: меняем только после согласования в чате команды.

## Один раз, перед началом

```powershell
git clone https://github.com/dam1r-dev/hackathon_MITU_2026.git
cd hackathon_MITU_2026
git checkout -b <ветка>
```

Имена веток: `core/<тема>`, `front/<тема>`, `docs/<тема>`. Дальше открой папку в Claude Code, он сам прочитает `CLAUDE.md`.

Бэкенд локально:

```powershell
python -m venv .venv
.venv\Scripts\pip install -r backend\requirements.txt
.venv\Scripts\python -m uvicorn backend.app.main:app --port 8000
```

Фронтенд локально:

```powershell
cd frontend
npm install
npm run dev
```

## Как коммитить (Claude сам не коммитит)

1. Claude закончил кусок работы и проверил его.
2. Claude выводит список изменённых файлов и кнопку «Commit» (в приложении) или готовые команды (в CLI).
3. Ты нажимаешь кнопку или запускаешь команды сам:

```powershell
git add <файлы>
git commit -m "Короткое сообщение"
git pull --rebase origin main
git push -u origin <ветка>
```

4. Сливай в `main` маленькими кусками и часто, чтобы конфликтов было мало.

## Стартовые промпты (вставь в первую сессию Claude)

### A: Дамир, ядро

```
Прочитай CLAUDE.md, docs/CONTRACT.md и docs/TEAM.md. Ты роль A (ядро): работаешь только в backend/app/.
Задачи по порядку:
1) заменить заглушку fit() в backend/app/matching.py на эмбеддинги (multilingual-e5-small, посчитанные заранее при старте) с двусторонним скором sqrt(fit(A->B)*fit(B->A));
2) объяснения, you_give/they_give и icebreaker читать из data/explanations.json (его делает Дулат); если записи нет, использовать шаблонный текст;
3) пересчёт после обратной связи (/api/feedback) и реальные координаты для /api/graph (например UMAP по эмбеддингам);
4) ответ /api/recommend быстрее 3 секунд.
Не делай git commit и git push: после каждой задачи покажи файлы и предложи сообщение коммита.
```

### B: фронт и дизайн

```
Прочитай CLAUDE.md, docs/CONTRACT.md и docs/TEAM.md. Ты роль B (фронт и дизайн): работаешь только в frontend/.
Сначала используй скиллы frontend-design и ui-ux-pro-max и предложи дизайн-систему (палитра, шрифты, компоненты) в frontend/src/styles/tokens.css, потом делай экраны:
1) анкета (mobile-first), 2) выдача топ-5 с анимацией и подсветкой общих тегов, 3) карта зала (граф участников, твоя пятёрка подсвечена), 4) переключатель kk/ru/en, 5) страница для QR.
Для каждого экрана: состояния загрузки, пусто, ошибка. Данные бери только через frontend/src/api.ts по контракту.
Не делай git commit и git push: после каждой задачи покажи файлы и предложи сообщение коммита.
```

### C: Дулат, данные, бэкенд-скрипты и питч

```
Прочитай CLAUDE.md, docs/CONTRACT.md и docs/TEAM.md. Ты роль C: работаешь в data/, backend/scripts/, backend/tests/, docs/, README.md и docker-compose.yml. В backend/app/ не правишь ничего, это зона Дамира.
Задачи по порядку:
1) data/generate_profiles.py: 100+ вымышленных анкет по контракту (все 6 целей, разные роли и стеки, био на kk/ru/en), результат в data/profiles.json. Это обязательный пункт, делай первым;
2) backend/scripts/precompute_explanations.py: для пар анкет заранее генерирует через LLM explanation, you_give, they_give и icebreaker, результат в data/explanations.json (формат согласуй с Дамиром);
3) backend/tests/: ищущему работу никогда не показывают других ищущих, топ-5 всегда ровно 5, ответ быстрее 3 секунд;
4) проверка docker compose up на чистой машине, README, затем презентация (до 10 слайдов) и сценарий демо на 3 минуты.
Не делай git commit и git push: после каждой задачи покажи файлы и предложи сообщение коммита.
```
